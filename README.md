## 三点必须先看清

1. **源码未加固，但 `apk/` 里的两个包是官方加固签名包** —— 二者并不对应。APK 是按你的选择直接上传的原版产物，源码是另一套去掉校验的代码。不要用这份源码去解释或修改那两个 APK 的行为。
2. **去掉加固后，访问名单挡不住改包** —— 名单判定跑在客户端，只要源码公开、包可改包，任何人都能删掉判定逻辑。它只剩「提示 / 自助控制」的意义，不再是安全边界。
3. **源码未经编译验证** —— 本环境没有 Android SDK，只做了 JS 语法与 Java 语法解析校验。`./gradlew assembleDebug` 需你在本地 Android Studio 里跑一遍。

## 访问名单（仅 v1.2.18）

按 GitHub **数字 ID** 判定，实现在 `app/src/main/assets/web/js/blocklist.js`：

- 名单为远程 Gist 的 `policy.txt`，一行一个数字 ID，`#` 开头为注释
- 判定按「没拿到」的原因分流：**404 / 空文件（`miss`）= 清缓存、放行所有人**；**网络故障 / 超时（`unknown`）= 退回本地缓存 → 内置基线**（fail-closed）；拿不到身份时用本机记住的 ID 判
- 换账号 / 重新登录时按真实 ID 重判
- 原历史版本**漏了 `index.html` 的 script 引入**，本次已补上 `<script src="js/blocklist.js">`，否则 `window.Blocklist` 永远不存在、功能完全不生效

> ⚠️ **实测（2026-11-03）：原实现内置的 Gist `e907901d784cdd8f2c70bff1c935d9be` 已返回 404。**
> 代码把两种「没拿到」分开处理：**404 / 空文件（`miss`）= 清缓存并放行所有人**；
> 只有网络故障 / 超时（`unknown`）才退回缓存 → 内置基线（fail-closed）。
> 所以当前名单源 404 的实际效果是**名单完全失效、所有人都能进**，而不是拦住所有人 ——
> 在换掉地址之前，往名单里加 ID 不会有任何效果。
> 上线前把 `blocklist.js` 第 56–60 行的 URL（base64 编码）换成有效的 `policy.txt` 地址。
>
> **名单支持陆续增添**：改远程文本即可，不用重新发版。格式：一行一个纯数字 ID，
> 空行与 `#` 开头的整行忽略；**不支持行内注释**（`349656672 # 张三` 整行会被丢弃）。
> 文件为空 / 只剩注释 = 放行所有人，适合从空名单开始逐个添加。
> 注意：`merge()` 恒把内置基线 `70214970` 并入，这个 ID 无法通过远程名单解封。

## 构建

```bash
cd v1.2.18
./gradlew assembleDebug
```

`build-apk.sh` / `set-version.sh` 里对 `tools/gen-guard.py`、`GuardKeys.java` 都有 `-f` 存在性守卫，防护链文件移除后会自动跳过，无需改脚本。
